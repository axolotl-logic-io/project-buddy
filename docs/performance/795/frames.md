# Route frame ownership

Issue [#795](https://github.com/axolotl-logic-io/project-buddy/issues/795) moves content-width ownership into segment layouts. It preserves the shared header, session validation, ownership predicates, data queries, purchases and navigation scroll ownership.

The workspace supplies a full-width flex container. Route layouts choose one of three existing column roles: the ordinary reading column, Home's full-width atlas, or the wider editor surface. The layouts contain no data reads and remain Server Components. Next nests loading, error and page content inside these layouts. Width therefore does not depend on whether an asynchronous atlas or Workshop descendant has arrived.

Ordinary routes receive explicit layouts to preserve their previous reading width after moving width ownership out of the workspace. Existing account, quest-list and adventure-list layouts retain their headings and controls. The pattern shares three frame components and semantic CSS roles; it introduces no theme or design system. Signed-out routes retain their existing frames.

Home loading now reserves an atlas region with its title and decorative placeholders. Quest loading reserves a title/actions row, status/action space, Progress and Adventures sections. The quest's loaded sections use the same minimum-height role for empty and populated content. Quest loading supplies one labelled busy status for the whole fallback; its shapes remain decorative and hidden from assistive technology. Other skeleton consumers retain their existing labelled status. No fake adventure rows become accessible data. Empty content remains inside the route frame. Home, quest overview and the three definition editors have segment error boundaries inside their layouts; these reuse the existing shared error content, retry and newer-build reload behavior. Errors in a layout itself still reach the root error boundary, which retains the ordinary reading column. Missing or inaccessible routes retain the existing generic not-found treatment.

The editor loading surface reserves its heading and editing area. The independently approved [Workshop Focus and Drawer work](https://github.com/axolotl-logic-io/project-buddy/pull/808) moves test controls to an initially closed drawer. This change coordinates frame width with that work and does not reproduce its UI. Measurements compare the integration editor with this branch's geometry; they do not measure the drawer branch.

## Exceptions and tradeoffs

Frames reserve semantic regions, not an exact row count or the height of arbitrary user text. Long quest names, additional adventures, first-visit introductions, conditional owner controls, member lists and form errors can legitimately grow a page. Those changes remain observable rather than being hidden behind a fixed-height crop. Error states retain the column width without pretending to contain a successful form or list. Home errors add an inner ordinary reading column inside the unchanged full-width Home frame, retaining phone gutters and desktop reading width.

The quest still resolves its existing parallel data group before rendering the page. This change does not add a client fetch waterfall or import Suspense. The site header and its navigation remain outside the segment loading boundary. Authentication and authorization remain prerequisites for private data.

Home's decorative background still follows the active atlas; its background changes do not control ancestor geometry. Home loading always renders inactive decoration. HomeAtlas also starts inactive in server markup, because an Activity first mounted hidden has not run layout effects. Its layout effect activates decoration only while visible and marks it inactive on cleanup when cached. Cleanup alone did not cover loading or a first-hidden mount. The editor retains its current behavior until the drawer work merges. Full editor form-height matching is intentionally outside the three shared column roles. Until the independent drawer change merges, the loaded editor still has side-by-side edit/test columns while its loading surface reserves the future full-width form. This is an explicit compatibility tradeoff agreed with that owner, not a claim that placeholder and loaded descendants have identical positions. The geometry observer covers frame/input rectangles and browser shift sources; low shift sums alone cannot establish exact descendant alignment. Reconciliation with the drawer remains a merge dependency.

## Phone breadcrumb alternative

The provisional phone Quests-to-Home transition retained a main-region shift of about 0.05723, above the candidate 0.05 transition sum. The breadcrumb row disappears on Home, changing main's document origin from 112 to 60. This occurs in both builds and is not removed from the totals as a click-associated shift.

A source prototype adds a current-page Home label in the existing breadcrumb row. It reserves meaningful location content instead of an empty spacer, leaving all existing parent destinations and current-page semantics intact. The tradeoff is a taller Home header and a pinned Home location row, following the existing breadcrumb policy. No atlas-dependent header style is added. This alternative has not been validated or included in an after-capture claim.
