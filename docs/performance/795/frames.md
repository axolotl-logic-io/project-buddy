# Route frame ownership

Issue [#795](https://github.com/axolotl-logic-io/project-buddy/issues/795) moves content-width ownership into segment layouts. It preserves the shared header, session validation, ownership predicates, data queries, purchases and navigation scroll ownership.

The workspace supplies a full-width flex container. Route layouts choose one of three existing column roles: the ordinary reading column, Home's full-width atlas, or the wider editor surface. The new frame wrappers perform no data reads and remain Server Components; existing list layouts retain their reads. Next nests loading, error and page content inside these layouts. Width therefore does not depend on whether an asynchronous atlas or Workshop descendant has arrived.

Ordinary routes receive explicit layouts to preserve their previous reading width after moving width ownership out of the workspace. Existing account, quest-list and adventure-list layouts retain their headings and controls. The pattern shares three frame components and semantic CSS roles; it introduces no theme or design system. Signed-out routes retain their existing frames.

Home loading now reserves an atlas region with its title and decorative placeholders. Quest loading reserves a title/actions row, status/action space, Progress and Adventures sections. The quest's loaded sections use the same minimum-height role for empty and populated content. Quest loading supplies one labelled busy status for the whole fallback; its shapes remain decorative and hidden from assistive technology. Other skeleton consumers retain their existing labelled status. No fake adventure rows become accessible data. Empty content remains inside the route frame. Home, quest overview and the three definition editors have segment error boundaries inside their layouts; these reuse the existing shared error content, retry and newer-build reload behavior. Errors in a layout itself still reach the root error boundary, which retains the ordinary reading column. Missing or inaccessible routes retain the existing generic not-found treatment.

The editor loading surface reserves its heading and editing area. The independently approved [Workshop Focus and Drawer work](https://github.com/axolotl-logic-io/project-buddy/pull/808) moves test controls to an initially closed drawer. This change coordinates frame width with that work and does not reproduce its UI. The final pair compares integration after that actual merge with the same drawer behavior plus these static frames; it measures the real loaded editor with its drawer initially closed.

## Exceptions and tradeoffs

Frames reserve semantic regions, not an exact row count or the height of arbitrary user text. Long quest names, additional adventures, first-visit introductions, conditional owner controls, member lists and form errors can legitimately grow a page. Those changes remain observable rather than being hidden behind a fixed-height crop. Error states retain the column width without pretending to contain a successful form or list. Home errors add an inner ordinary reading column inside the unchanged full-width Home frame, retaining phone gutters and desktop reading width.

The quest still resolves its existing parallel data group before rendering the page. This change does not add a client fetch waterfall or import Suspense. The site header and its navigation remain outside the segment loading boundary. Authentication and authorization remain prerequisites for private data.

Home's decorative background still follows the active atlas; its background changes do not control ancestor geometry. Home loading always renders inactive decoration. HomeAtlas also starts inactive in server markup, because an Activity first mounted hidden has not run layout effects. Its layout effect activates decoration only while visible and marks it inactive on cleanup when cached. Cleanup alone did not cover loading or a first-hidden mount. On direct loads the decorative artwork now appears after hydration; without JavaScript it stays absent, while the frame and content remain available. Full editor form-height matching remains outside the three shared column roles. Both final variants use the actual merged drawer implementation; there is no in-flow test pane. The geometry observer covers frame/input rectangles and browser shift sources; low sums alone cannot establish exact descendant alignment.

## Home location-row tradeoff

The initial frame-only candidate retained phone Quests→Home movement around 0.05723, above the 0.05 transition limit: removing Home's breadcrumb row moved main from document Y 112 to 60. That shift remained included even though a route click preceded it. The parent tested an alternative that renders a meaningful current-page Home label in the existing location row. It preserves parent destinations, current-page semantics and existing scroll ownership, with no atlas-dependent header rule.

The tradeoff is a taller Home header and its existing pinned location row: initial 112 px instead of 64 px in this fixture, and pinned row 52 px. Workshop already respects that offset; its short-height behavior and modal drawer remain unchanged. The alternative passed 92 focused header/Library cases and a separate three-pair pilot before final reconciliation. The completed ten-pair post-drawer cohort records zero after shifts in every Home/Quests transition on desktop and phone.

The pilot's queued check was canceled before starting for the common-baseline priority reservation; it is unrun, not pass/fail. Its first resumed browser run exposed six deterministic missing-theme-kit failures. Applying the theme explicitly and exercising both themes corrected the test setup, with no assertion/deadline weakening. The earlier copy preparation failure produced zero observations and remains recorded. Final source checks and measurements above supersede those provisional stages without deleting their history.
